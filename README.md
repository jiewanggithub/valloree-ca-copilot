# Vallorée CA Copilot

Drafts **three on-brand WeChat messages in Chinese** for a luxury Client Advisor (CA). It covers six scenarios: greeting, recommendation,
after-care, reactivation, event invitation and price objection. The brand, *Maison Vallorée (瓦洛蕾)*, is a fictional Geneva house that makes
high jewellery and watches. All clients, products and conversations are fictional.

## Quick start

```bash
conda env create -f environment.yml      # creates env "ca-copilot"
conda activate ca-copilot
cp .env.example .env                     # add DEEPSEEK_API_KEY (optionally DASHSCOPE_API_KEY for a Qwen judge)
./start.sh                               # web app -> http://localhost:8000
```

The web app has two pages:
- **生成 Generate**: pick a scenario and a client, edit the WeChat history and products, and generate three drafts. Each draft shows the fact
  IDs it cites, guardrail flags and what the fact-check removed, with copy and "放入对话预览" (preview in chat) buttons. A timing warning
  appears when sending now would break a client preference.
- **测试集评估 Evaluation**: all 50 test cases with v1 / v2 / v3 outputs side by side, review verdicts and judge scores. It reads saved
  results, so it makes no API calls.

`streamlit run app.py` is the earlier, minimal demo and still works.

Run on a new input from Python:

```python
from ca_copilot.data import load_clients, load_products
from ca_copilot.pipeline import Generator
from ca_copilot.schema import Request, Turn

clients, products = load_clients(), load_products()
req = Request(scenario="price_objection", today="2026-11-20", client=clients["C03"],
              history=[Turn(speaker="client", time="2026-11-20 10:00", text="能便宜一点吗？")],
              products=[products["LRR-B-01"]])
for c in Generator().generate(req).candidates:
    print(c.angle, c.message, c.issues)
```

## Evaluate

```bash
python scripts/run_eval.py --version v3          # generate + judge all 50 cases -> results/v3/
python scripts/run_eval.py --version v3 --rejudge  # re-score existing outputs with the current judge
python scripts/build_report.py v1 v2 v3          # metrics + deliverables/test_cases_v3.xlsx
python scripts/make_charts.py && python scripts/build_docs.py   # charts + report HTML/PDF
python -m pytest -q tests                        # guardrail regression tests
```

Note: `docs/report.html` is generated by `scripts/build_docs.py`. Change the report in that script, not in the HTML.

## Layout

| Path | What |
|---|---|
| `brand/` | Brand bible (assumptions, voice, compliance rules) and product catalogue |
| `data/clients.yaml`, `data/cases.yaml` | 20 CRM personas, 50 test cases (each notes what it tests) |
| `data/human_review_v*.yaml` | Manual review labels per version (OK / EDIT / UNACCEPTABLE + defect code) |
| `ca_copilot/context.py` | Deterministic signals, preference rules, numbered fact sheet |
| `ca_copilot/scenarios.py`, `prompts.py` | Scenario playbooks (3 angles each), prompts, critic prompt |
| `ca_copilot/pipeline.py` | Generate → fact-check critic → guardrails → repair |
| `ca_copilot/guardrails.py` | Rule checks (discounts, 广告法 absolutes, investment claims, fabricated prices/new arrivals, policy misuse …) |
| `server.py`, `frontend/` | FastAPI backend + single-page web app (no build step) |
| `ca_copilot/judge.py` | LLM judge: rubric with 6 dimensions + hard fail, fact-check first |
| `snapshots/` | Frozen code of v1, v2, v3 (each result file records its version) |
| `results/` | Raw outputs + judge scores per version; `_judge_calibration/` holds earlier judge runs |
| `docs/` | Report source, architecture diagram, figures |
